# 再生エンジン設計

状態: 承認済み（2026-11-12）。実装の進み具合は [タスク08](../tasks/08-episode-engine.md)。前提は [CONCEPT.md](../CONCEPT.md) と [技術選定](../tasks/07-tech-selection.md)。

## 設計の柱

1. **音声の再生位置がすべての時計**。画面の状態は「再生位置 t から計算した結果」として毎フレーム求める。イベントを順に積み上げる作りにしない。こうすると、目次ジャンプやシークは再生位置を変えるだけで正しい画面になる。
2. **聞こえるものはすべて1本のMP3に入れる**。声、BGM、muiの効果音を生成時にミックスする。画面を消しても番組として成立する。エンジンが別に鳴らすのは、つつきなど操作への反応音だけ。
3. **一度公開したファイルは書き換えない**。過去回が変わらないことをファイルの置き方で保証する。
4. **その回だけの仕掛けは隔離する**。壊れても番組本体は止まらない。

## URLとファイルの置き方

| パス | 中身 | 置き場所 | 書き換え |
|---|---|---|---|
| `/` | 最新回への入口、アーカイブ一覧、おたよりフォーム | Workerの静的アセット | する |
| `/episodes.json` | 全回の一覧（日付、タイトル、公開フラグ） | R2 | する（公開・非公開の切り替え） |
| `/ep/2026-11-12/` | その回のページ、`episode.json`、`audio.mp3`、画像、その回だけの仕掛け | R2 | しない |
| `/engine/<ハッシュ>/` | エンジンのJS・CSS | R2 | しない |
| `/chars/<ハッシュ>/` | キャラクター素材とリグ定義 | R2 | しない |

エンジンとキャラクター素材は、内容から求めたハッシュ名のフォルダに置き、各回がそのハッシュを指す。エンジンを更新すると新しいハッシュのフォルダができ、古い回は古いフォルダを指し続ける。「各回にエンジンを丸ごとコピーする」のと同じ保証を、容量を増やさずに得られる。

Workerは、R2から配信するときにRangeリクエスト（音声の途中から読む要求）に対応する。対応しないとシークできない。

## episode.json

1回分のすべてを記述する。エンジンはこのファイルと音声だけで番組を再生する。

```json
{
  "schema": 1,
  "date": "2026-11-12",
  "title": "今日のタイトル",
  "duration": 612.4,
  "audio": "audio.mp3",
  "engine": "/engine/ab12cd34/",
  "characters": {
    "ryopon": "/chars/11aa22bb/ryopon/",
    "mui": "/chars/11aa22bb/mui/"
  },
  "chapters": [
    { "id": "op", "title": "オープニング", "start": 0 },
    {
      "id": "news", "title": "ニュース", "start": 31.0,
      "items": [
        { "title": "1本目の見出し", "start": 31.0 },
        { "title": "2本目の見出し", "start": 95.5 }
      ]
    }
  ],
  "tracks": {
    "subtitle":    [ { "start": 0.0, "end": 3.2, "who": "ryopon", "text": "おはようございます。" } ],
    "ryoponMouth": [ { "start": 0.00, "end": 0.12, "shape": "open" } ],
    "ryoponFace":  [ { "start": 0.0, "end": 31.0, "face": "smile" } ],
    "ryoponPose":  [ { "start": 0.0, "end": 4.0, "pose": "wave" } ],
    "muiFace":     [ { "start": 3.4, "end": 6.0, "face": "surprise" } ],
    "muiPose":     [ { "start": 3.4, "end": 6.0, "pose": "earsUp" } ],
    "emote":       [ { "start": 3.4, "end": 5.0, "who": "mui", "symbol": "!" } ],
    "scene":       [ { "start": 0.0, "end": 612.4, "background": "img/bg.png" } ],
    "card":        [ { "start": 31.0, "end": 95.5, "kind": "news", "title": "…", "body": "…", "image": null, "source": { "name": "媒体名", "url": "https://…" } } ],
    "prop":        [ { "start": 40.0, "end": 95.5, "id": "robot", "image": "img/robot.png", "x": 0.7, "y": 0.6, "onTap": "wobble", "note": "タップで出る一言" } ],
    "custom":      [ { "start": 120.0, "end": 180.0, "module": "custom/planet.js" } ]
  },
  "sources": [ { "title": "記事名", "name": "媒体名", "url": "https://…" } ],
  "credits": [ "VOICEVOX:（声の名前）" ]
}
```

- 各トラックは「開始と終了を持つ区間」の並び。時刻 t の画面は、各トラックで t を含む区間を探して決める。区間がないときは既定値（無表情、基本ポーズ）。
- `schema` は形式の版。エンジンは自分が対応する版だけを読む。古い回は古いエンジンを指すので、形式を変えても過去回に影響しない。
- muiの心の声は `subtitle` に `who: "mui"` で入れる。効果音は音声側に入っている。
- 口の形は、VOICEVOXが返す音素の時刻から生成時に作る。

## 画面の構成

2026-11-12 に全画面・スクロールなしの構成へ改めた。

- **主役は舞台だけ**。背景を画面全体に広げ、番組表、ニュースのカード、字幕、操作盤は紙のような静かな面にして重ねる。
- **ページ自体はスクロールしない**。長いもの（番組表、台本と出典）は重ねて開く面にし、その中だけがスクロールする。
- **舞台**: 正方形の固定座標（1000×1000）で作り、画面に合わせて拡大縮小する。キャラクター、小物、その回だけの仕掛けはこの座標に置く。
- **背景**: 舞台より広い 2800×2800 で描き、舞台の左上が (900, 400) に来る。はみ出した部分が、横長の画面では左右、縦長の画面では上下を埋める。21:9 のモニターや 9:22 のスマホでも余白が出ない広さ。
- **PC（横長）**: 中央に舞台、左に番組表、右にニュースのカード、最下部に操作盤。字幕は舞台の下端。
- **スマホ（縦長）**: 上に舞台、その下に字幕とカード、最下部に操作盤。番組表は操作盤のボタンから開く。
- **操作盤**: シークバーはラジオのダイヤル。細かい目盛りが一定秒ごと、長い目盛りがコーナーの区切りで、アクセント色の針が再生位置を示す。
- 文字はDOMなので、選択やリンクがそのまま使える。

### 見た目の方針

[unslop](https://github.com/heydamir/unslop)（Damir Sokolovsky、CC BY 4.0）の手順で決めた。

- **性格**: のんびり、素直、すこし手づくり
- **世界**: 朝の谷。紙の番組表と、ラジオのダイヤル
- **この番組だけの細部**: ダイヤル目盛りのシークバー
- 色は暖色寄りの無彩色1系統と、アクセント1色（`#c2542d`）。アクセントは開始ボタン、ダイヤルの針、再生中のコーナーの印だけに使う。
- 余白は4pxの倍数。文字の太さは400と500（番組名だけ600）。アイコンは [lucide](https://lucide.dev)（ISC License）の線画を1つの大きさで使う。
- キャラクターの動きだけは、人形らしく少し行き過ぎて戻る。UIの動きは1種類の緩急にそろえる。

## キャラクターのリグ

キャラクターごとに `rig.json` を置き、パーツの重ね順・位置・切り替えを定義する。

- **パーツ**: 体、頭、目、眉、口、腕（前足）、耳など。重ね順と基準点を持つ。
- **表情**: 目・眉・口などのパーツの組み合わせ。初期は5種（驚き、笑い、無表情、泣き、虚無）とmuiのジト目。
- **ポーズ**: 腕や耳などのパーツの差し替えと、位置・角度。
- **口パク**: 閉じ、半開き、開きの3枚を、音素の時刻に合わせて切り替える。muiは口パクなし。
- **自動の動き**: まばたき（不定期）、呼吸の揺れ。台本の指定とは無関係に常に動く。
- **切り替えの動き**: 表情やポーズが変わる瞬間に、小さく弾む動きを付ける。
- **つつき**: キャラクターをタップすると、反応の動きと音がランダムに出る。番組の進行には影響せず、終わると台本の状態に戻る。

パーツ規格の詳細（キャンバスサイズ、命名、基準点）は [タスク05](../tasks/05-character-assets.md) で決める。本物の素材ができるまでは、丸や四角の仮素材で開発する。

## 再生の流れと操作

- **開始画面**: 日付、タイトル、目次と「番組をはじめる」ボタンを出す。ボタンを押した時点で音声を再生する。ブラウザの自動再生制限はこれで回避できる。
- **操作**: 再生・一時停止、ダイヤル（シーク）、番組表、10秒戻し・送り、再生速度、字幕の表示切り替え。音量は端末側で調整する。
- **ロック画面**: Media Session API で、番組名の表示と、前後のコーナーへの移動に対応する。
- **続きから再生**: 再生位置をブラウザに保存し、同じ回を開き直したら続きから始められる。
- **リンク**: `/ep/2026-11-12/#news` のように、コーナーを指定して開ける。
- **全文と出典**: プレーヤーの下に、台本の全文と出典の一覧を載せる。

## その回だけの仕掛け（custom）

決まった形のモジュールとして各回のフォルダに置く。

```ts
export default {
  mount(el: HTMLElement, ctx: CustomContext): void,  // 表示開始
  update(t: number): void,                            // 毎フレーム。t は区間の開始からの秒数
  unmount(): void,                                    // 表示終了
}
```

- 描画できるのは、エンジンが渡す `el`（舞台上の専用の枠）の中だけ。
- `ctx` で使えるのは、舞台の座標、その回の画像、キャラクターへの表情・ポーズの一時的な指示、効果音の再生。
- 外部への通信、ブラウザへの保存はさせない。ページにCSP（外部への通信を禁止する設定）を付ける。AIが書いたコードを無人で公開するための安全策を兼ねる。

壊れたときの扱いは2段構え。

1. **公開前**: ヘッドレスブラウザで全区間を早送りで再生し、エラーが出ないか確認する。エラーが出たら、`custom` トラックを空にした通常版を作り直して公開する。
2. **再生中**: `mount`・`update`・`unmount` の呼び出しをすべて例外処理で囲む。エラーが出たらその仕掛けだけを消し、番組は続ける。

## 実装

- TypeScript + Vite。UIフレームワークは使わない。
- 動きはCSSの変形とWeb Animations APIで作る。
- テストは、サンプルの1回分を使ったヘッドレスブラウザでの通し再生（Playwright）。公開前チェックと同じ仕組みを使う。

## 作る順番

1. 音声、字幕、目次、シークだけのプレーヤー（サンプル音声と手書きの `episode.json`）
2. 仮素材でのキャラクター表示（表情、ポーズ、口パク、まばたき、つつき）
3. 背景、カード、小物、記号演出
4. その回だけの仕掛けの差し込み口と、壊れたときの切り替え
5. R2とWorkerへの配置、アーカイブ一覧

## 決定事項（2026-11-12）

- 舞台は正方形。情報欄はスマホでは下、PCでは右に置く。
- 本物の素材ができるまで、仮素材で開発を進める。
- 口パクは3枚（閉じ、半開き、開き）。
- キャラクターの各パーツは、キャンバス全体と同じサイズの画像として書き出す。位置合わせの指定が要らなくなる。
